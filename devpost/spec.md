# ムダ連鎖 — Technical Spec

2026-10-05 カイロスの技術提案を本人が「よいです!! お願いします」で承認。対象スマートフォンのOS／ブラウザは未回答・要確認。PCでの実装と検証を先に進め、実機オフライン検証の証明は別途行う。

## How This Works, In Plain Language

スマートフォンのブラウザで遊べるアプリとして作る。最初にゲーム一式を端末へ保存し、その後は通信なしでも開ける構成を提案する。街とドローンを立体の小さなブロックで描き、指の移動・停止・円運動をゲームへ渡す。

吸収した物、エネルギー、スコア、ターゲットの残り体力とプレイ時間は端末内に保存する。閉じている間はゲームも時間も止まり、戻るとその続きから再開する提案。アカウント・クラウド同期は使わない。同じブラウザ・同じ配信先での再開が対象で、別端末への移行は含めない。

## The Core Journey Through the System

1. 起動時に保存データを確認。既存プレイがあれば復元、なければ街を生成する。
2. 好きな位置で指を当ててずらす → 入力処理が移動量と方向を計算 → ドローンが動く → 通過した物が吸収される。
3. 指を止めて長押し → ためる状態へ移る → ドローンを停止し、周辺の物が渦を描いて吸い込まれる。
4. 接触した指の急な円運動 → 回転検出がハイパー成立を通知 → 画面で成立が分かる。
5. 指を離す → 直前の移動方向へ通常／ハイパー放出 → 放出の衝撃による基礎ダメージと、方向を合わせた弾の命中による追加ダメージがスコア加算・弱体化へつながる提案。
6. 5分で未撃破 → ゲームを止めて「つづける？」 → 続行を選ぶと同じターゲットへのプレイを再開。
7. 中断 → 進行を保存し、入力を解除 → 次回起動で復元。

PRD ref: `prd.md > The Core Journey`。

## Stack

以下は2026-10-05に本人承認された推奨構成。

- JavaScript ES modules + HTML/CSS。余分な画面フレームワークを使わず、入力とゲームの検証を小さく保つ。
- [Three.js](https://threejs.org/docs/)：ボクセル調ローポリの街・ドローンと球状エフェクトを描画。2026-10-05にnpmの安定版0.186.1を確認して導入、package-lock.jsonで固定。正式なパッケージをローカル配信し、実行時CDNを使わない。配信用一式にも依存のLICENSEを添える。
- ブラウザの [Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)：タッチとPCのマウス入力。
- [Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) とCache Storage：アプリ本体のオフライン起動。
- [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)：小規模なゲーム進行の保存。ユーザーのブラウザデータ削除で消える。
- Node.js：開発時の静的配信・ビルド・ロジックテスト用。このPCではv22.14.0、npm 11.2.0を確認済み。利用者のスマートフォンにはNode.js不要。

- 対象：スマートフォンのモダンブラウザ。OS・ブラウザ・実機は要確認。PCでもマウスで操作検証できるようにする。
- 実装後の開発コマンド予定：作業フォルダで `npm install` → `npm run dev` → `http://localhost:4173`。ポート使用中は黙って別ポートへ変えず案内する。
- リリース検証予定：`npm run build` → `npm run preview` → `http://localhost:4173`。Service Workerの検証はリリース用ビルドで行う。
- スマートフォンのオフライン起動検証はHTTPS配信、または対象端末に適した安全なローカル接続が必要。PCのLAN内HTTPアドレスへのアクセスだけではService Workerによるスマートフォンのオフライン起動を証明しない。
- 初回はオンラインでアプリ全体のキャッシュ完了を確認してから機内モードにする。キャッシュ前の初回起動はオフライン対応の対象外。
- スマートフォン向け配信先は未選定。外部公開は別途本人の明示許可が必要。HTTPSの実機検証経路を端末確認後に決める。
- 提出には公開コードリポジトリと3分未満の公開デモ動画が必要。配信URLは動画を代替しない。

## Components

### Input and Gesture Detection

最初の1本の指を追跡し、追加の指は無視する。プレイ領域のページスクロールを抑制し、pointer captureで円運動と離す操作を追う。

初期調整値の提案：直近の指移動が8 CSS px以内で350ms静止したらためる状態へ入る。移動中も同じ位置へ止めることで長押しに移行する。ためる状態に入った後の円運動を、移動入力へ戻さない。単なるドラッグの終了で通常放出する場合も、放出するエネルギーがなければ発射しない。

急回転は最近の座標・時刻から判定する。円の中心は押し始めた点に固定せず、軌跡から推定する。半径・円への近さ・同じ回転方向の累積角度・角速度を組み合わせ、直線や往復をハイパーと誤判定しない。暫定条件は半径12 CSS px以上、同方向の回転が約1周、約0.9秒以内。時計回り／反時計回りの両方を扱う。値は実機で調整する。

発射方向は最後の有効な移動方向を、ためる状態へ入った時点で保持する提案。円運動では方向を変えない。移動履歴がない初回はターゲット方向を初期照準にする提案。

`pointercancel`・画面切り替え・フォーカス喪失では押下を解除し、勝手に放出しない。
PRD ref: `prd.md > 長押し・回転・解放`, `ドローンによる吸収`。

### Game Simulation

描画に依存しないゲーム進行を持つ。街の物、ドローン座標、吸収量、弾、ターゲットHP、スコアと時間を更新する。距離判定で通過吸収／周辺吸引を分ける。吸引中の物を通常吸収と重複加算しない。

吸収したエネルギーを実際の放出へ変換する。PRDの「放出による保証される弱体化」を守るため、エネルギーを使った放出自体に衝撃波の基礎ダメージを持たせ、移動方向を合わせて弾を当てると追加ダメージを与える提案。衝撃波と直接命中は演出・加算原因を分ける。エネルギー0の操作にダメージは付けない。弱体化は永続し、放出を撃ち尽くしても回復しない。保持した照準を目で確認できるようにする。

通常／ハイパーの弾数・速度・倍率とターゲットHPは設定にまとめ、通常操作でも5分内の撃破を狙えるよう調整する。自動撃破は使わない。街の資源枯渇で進めなくならないよう、吸収済み地点への時間差再配置を提案する。
PRD ref: `prd.md > ドローンによる吸収`, `長押し・回転・解放`, `5分の区切り・続行・撃破`。

### Rendering and Effects

ゲーム進行の読み取り結果から描画。箱を組んだ街・ドローン、吸引渦、通常弾とビビッドなハイパー球、連続スコア表示。多数の球と物は上限と再利用で負荷を抑える。演出の完了をHP更新の条件にしない。
PRD ref: `prd.md > Look and Feel`, `長押し・回転・解放`。

### Session and Persistence

5分の未撃破時は進行と入力を止めて続行確認を表示。続行後は経過時間を表示し、同じ5分確認を毎フレーム繰り返さない提案。

localStorageにバージョン付きの進行データを保存。1秒間隔、吸収・放出・続行・撃破の節目、ページが隠れた時に保存する。最後の瞬間だけの保存へ依存しない。非表示中の進行と時間を停止する提案。

吸引中の物・飛んでいる弾も保存し、再開時の消失や重複命中を防ぐ。指の接触状態は保存しない。破損・非対応版のデータを検出したら説明を表示し、ユーザーが新規開始を選ぶまで勝手に上書きしない。
PRD ref: `prd.md > 中断からの再開`, `5分の区切り・続行・撃破`。

### Offline App Shell

リリース用HTML・JS・CSS・Three.js・manifest・アイコンを同じ配信元から配信してキャッシュ。実行中に外部フォント・CDN・APIを取得しない。キャッシュ完了を表示し、バージョン切替はプレイ途中に強制しない。キャッシュ保存とゲーム進行保存は別の仕組みとして検証する。
PRD ref: `prd.md > 5分の区切り・続行・撃破`, `中断からの再開`。

## Data Model

端末内の保存キー案：`muda-rensa:session:v1`。値はJSON。

- `schemaVersion`, `seed`, `phase`, `elapsedSeconds`, `continued`：同じ街と時間・続行状態の復元。
- `drone {x,z,heading,energy}`：位置・照準・エネルギー。
- `target {x,z,hp,maxHp}`：撃破対象と累積弱体化。
- `score`：整数の累積得点。
- `objects[] {id,kind,x,z,value,state,absorbProgress,respawnAt}`：未吸収・吸引中・再配置待ちの物。
- `projectiles[] {id,x,z,dx,dz,damage,life,hyper}`：放出途中の復元。命中済み弾は同じ更新で削除する。放出時の基礎ダメージは発射と同じ更新で適用・保存し、復元時に再適用しない。

復元時に型・有限値・上限・ID重複を検証する。画面座標・押下状態・派手な粒子は一時状態として再生成する。保存できない場合は「この端末では続きの保存ができません」と表示し、再開可能と偽らない。

## External Services and Dependencies

ゲーム実行時のAPI・ログイン・課金・分析送信は不要。開発時にnpmからThree.jsを取得する。配信先・公開リポジトリは未選定で、作成・公開をこの設計の承認だけで実行しない。

## Important Failure Modes

- **移動と回転の混同** → ためる状態に入ったら移動と照準更新を止める。円以外の軌跡もテストし、実機で調整する。
- **保存・キャッシュの制限** → 保存不可／オフライン準備未完了を別々に表示。再開・機内モードの成功は実機で確認する。
- **描画負荷やWebGL利用不可** → 球や解像度を制限。WebGL利用不可なら理由を表示し、動作成功とは扱わない。
